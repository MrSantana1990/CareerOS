## Gargalo #2

`inspect_application_queue` — função irmã de `execute_application_queue` (já corrigida no Cycle 001, PR #80) — tinha exatamente o mesmo bug estrutural, nunca corrigido: uma única página do Chrome reaproveitada para todas as vagas inspecionadas num único lote, sem nunca ser reciclada. Confirmado pelo padrão idêntico de código (`page = browser.pages[0] if browser.pages else await browser.new_page()` antes do loop, sem reciclagem).

## Correção

PR #85: mesma correção do Cycle 001 aplicada a `inspect_application_queue` — cada vaga fecha as páginas da anterior e abre uma nova ao final do próprio processamento. Exceção real (tipo + mensagem) agora capturada em `application["inspect_error"]` + evento `APPLICATION_INSPECT_FAILED`.

**Impacto:** eliminação confirmada da segunda maior causa isolada de falha real (249/519, 48% das FAILED). Combinado com o Cycle 001 (Page crashed em preparo), as duas causas isoladas mais frequentes de FAILED real foram eliminadas com evidência de produção.
